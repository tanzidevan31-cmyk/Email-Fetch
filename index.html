Hitting AADSTS90023? The Azure app is registered as a Web app

That error means Microsoft is refusing to redeem the refresh token in a browser because the app behind the client ID isn't a Single-Page Application. Two ways out — the two-minute registration fix below, or the automatic server-side fallback this page tries whenever its /api/token endpoint is deployed.

AADSTS90023

Fix 1 — Register the app as a Single-Page Application (recommended)

  1. Open the Azure portal → App registrations → the app whose client ID is in your account line.
  2. Go to Authentication in the left menu.
  3. Under Platform configurations, click Add a platform → choose Single-page application.
  4. Enter this site's own address — the URL where you deployed this page — as the Redirect URI. It must match exactly, including the trailing slash, in this form:
https://your-deployed-site.vercel.app/

Copy the address from your browser's address bar while you're on the deployed site, and paste it into Azure exactly as shown there.

  1. Click Configure, then Save. You can leave any existing Web platform in place — adding the SPA platform is what unblocks the browser token exchange.
  2. Come back here and paste your line again. No new refresh token is needed — the same line should now fetch.

Fix 2 — Automatic server-side fallback (no Azure change)

When the browser exchange fails with AADSTS90023, this page automatically retries the exact same exchange through POST /api/token on this same site — server-to-server calls aren't subject to the cross-origin rule, so a Web-app registration works. Nothing about the input changes, and credentials still live in memory only.

Deploying on Vercel? Add this one file next to index.html and the fallback is live:

// api/token.js — Vercel serverless function
export default async function handler(req, res) {
  if (req.method !== "POST")
    return res.status(405).json({ error: "method_not_allowed" });
  const { client_id, refresh_token } = req.body || {};
  if (!client_id || !refresh_token)
    return res.status(400).json({ error: "missing_fields" });
  const body = new URLSearchParams({
    client_id, refresh_token,
    grant_type: "refresh_token",
    scope: "https://graph.microsoft.com/Mail.Read"
      + " https://graph.microsoft.com/User.Read offline_access"
  });
  const r = await fetch(
    "https://login.microsoftonline.com/common/oauth2/v2.0/token",
    { method: "POST",
      headers: { "Content-Type": "application/x-www-form-urlencoded" },
      body });
  return res.status(r.status).json(await r.json());
}

The function is stateless — it forwards the exchange to Microsoft and returns the result. It stores nothing. On hosts without an /api/token endpoint, use Fix 1 instead.

Password never leaves the page

It's parsed only to validate the format. Sign-in happens with the refresh token — the password is never sent to Microsoft or anywhere else.

Browser-first, with a built-in fallback

The token exchange normally goes straight to login.microsoftonline.com and mail to graph.microsoft.com. Only if Microsoft blocks the browser exchange (AADSTS90023) does the page retry through this site's own /api/token endpoint — never a third-party relay.

Zero storage, by design

No localStorage, no cookies, no database. Credentials and mail live in page memory only — close the tab and they're gone.

How the fetch actually works

The refresh-token grant is the same flow desktop mail clients use — done in the browser first, with a server-side retry only when Microsoft blocks the browser exchange.

1
Parse the lineSplit on | into email, password, refresh token, and client ID — validated live as you paste.
2
Exchange for an access tokenPOST login.microsoftonline.com/common/oauth2/v2.0/token with grant_type=refresh_token and scopes Mail.Read + User.Read. If that returns AADSTS90023 (app registered as a Web app, not an SPA), the same exchange is automatically retried server-side via POST /api/token on this site. Tokens typically live ~60 minutes; if Microsoft rotates the refresh token, the new one is kept in memory.
3
Read mail from GraphGET graph.microsoft.com/v1.0/me/mailFolders/{folder}/messages for the list, and /me/messages/{id} for full bodies — HTML is sanitized with DOMPurify before it renders.
4
Close the tab — it's all goneAccess token, refresh token, and every loaded email exist only in JavaScript variables. The Wipe button in the inbox does the same thing on demand.

Publish it anywhere

This is one self-contained index.html — no build step, no environment variables. The only optional server piece is the /api/token fallback function, and only for Web-app registrations.

  1. GitHub: create a repo, add this file as index.html, commit & push.
